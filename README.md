# Ganciclovir and Valganciclovir for CMV Infection in Immunosuppressed Patients

An interactive, referenced walkthrough of the decision algorithm for ganciclovir and
valganciclovir use in cytomegalovirus (CMV) infection and disease across immunosuppressed
populations — solid organ transplant (SOT) and haematopoietic cell transplant (HCT)
recipients, HIV, haematological malignancy, and other causes of impaired cell-mediated
immunity. The algorithm forks on whether CMV infection or disease is already active:
serostatus/organ/induction-stratified **prevention** (four population-specific pathways —
SOT D+/R−, SOT R+, HCT R+, and managing leukopenia/neutropenia on prophylaxis) for patients
without active infection, or severity-led IV-versus-oral **treatment** induction, through a
shared immunosuppression/ART/retinitis step, weekly monitoring, an ANC checkpoint, a
viral-load/resistance checkpoint, and the treatment-response endpoint, for patients who
already have it. A standalone evidence summary (certainty-graded, from the review's own
synthesis) sits alongside the diagram. Every box can be selected to reveal, in one place:
what the step means, why the algorithm calls for it, and the sources behind it.

## Why this exists

A flowchart alone tells a reader *what* to do at each step but not *why* — and CMV
prevention/treatment in immunosuppressed patients is a field with genuinely divergent
strategies by population (prophylaxis vs preemptive therapy, letermovir vs valganciclovir,
fixed vs immunoguided duration) rather than one universal rule. This page keeps the original
algorithm exactly as authored, and attaches the clinical reasoning, the evidence certainty
behind each step, and the literature to each box without cluttering the diagram itself.

The algorithm this page presents is Figure 3 of an unpublished, blinded manuscript — a
systematic review with GRADE and MCID appraisal (PubMed/MEDLINE and WHO ICTRP, last search
16 November 2026; 392 records screened to 28 included studies, 14 RCTs, 6,118 patients, and
a 110-entry bibliography) — condensed into this project's structured template and built from
that condensation plus the authors' own figure, supplied separately as an image.

## Status

This is a working version, built to be tested on both desktop and mobile.

- **Source workflow — a new condensation path in this atlas:** the manuscript's own
  narrative text, tables and 110-entry bibliography were condensed using this project's
  usual structured prompt, but by **ChatGPT rather than Gemini** — the first time in this
  atlas a tool was condensed by a different external AI. Gemini had begun repeatedly
  erroring partway through this specific document (3–4 failures per attempt, truncating the
  reference list mid-entry at reference 5 of 110 on its one completed attempt), so the
  author switched condensation tools for this build; the same structured template and
  discrepancy-flagging conventions were used regardless of which AI ran it. ChatGPT's
  completed condensation came back in a single pass with all 110 references intact.
- **Figure fidelity:** every one of this tool's 16 box/diamond labels and sub-texts was
  independently cross-checked against the figure image, box by box, against the
  condensation's own Section 4 transcription — **zero** discrepancies found.
- **Reference verification — explicit, author-granted exception (the ninth in this atlas,
  with a different basis from the previous eight):** every prior exception in this atlas
  (`epinephrine-revisited-protocol`, `ketamine-indications-protocol`,
  `haloperidol-adjunct-protocol`, `geriatric-pain-protocol`,
  `metoclopramide-ondansetron-protocol`, `spontaneous-pneumothorax-protocol`,
  `button-battery-protocol`, `beta-lactam-infusion-protocol`) was granted because the
  manuscript's own reference list had **already** been checked by Dr. Karcıoğlu, by a prior
  AI condensation pass, or both. For this tool, verification was waived for a different
  reason, given explicitly by the author: the bibliography will be checked **later**, by the
  author team's own clinicians, specifically so this session's context would not be spent on
  a verification pass. The reference list was **not** independently re-verified against
  primary sources for this build, and was not claimed to be already-checked by anyone else
  either — every entry's `kind` field says plainly that verification was not performed here.
  See `assets/content.js`'s header comment and `METHODOLOGY.md` for the full precedent
  record, including why this instance is documented with different wording from the eight
  before it.
- **Calculator candidates:** none. This project's structured condensation prompt always asks
  whether the source text names a weighted, multi-criterion clinical score or a named
  renal-function equation; for this manuscript the answer was no. The ANC cutoff, the
  qualitative severity assessment, and the "renal dosing" label that appear on the diagram
  are single thresholds or general instructions, not named scoring systems, so this tool has
  no interactive calculator.

## Disclaimer

This is an academic / educational reference tool, not a substitute for institutional protocol
or bedside clinical judgement. This algorithm applies to immunosuppressed patients (SOT and
HCT recipients, people with advanced HIV, haematological malignancy, or other causes of
impaired cell-mediated immunity) at risk of, or with, CMV infection or disease; it should not
be extrapolated to immunocompetent patients. This tool's reference list is reproduced
directly from the source manuscript's own bibliography and was not independently re-verified
for this build — see Status above.

## How it's built

Plain HTML/CSS/JS, no build step and no framework — a single static site that GitHub Pages
can serve directly.

```
index.html          page structure — masthead, the diagram (entry, the active-infection
                     decision, PREVENTION and TREATMENT side by side, PREVENTION's four
                     population-specific boxes, TREATMENT's IV/oral route split, the shared
                     immunosuppression/ART/retinitis step, weekly monitoring, the ANC and
                     resistance checkpoints, the response endpoint, and the standalone
                     evidence summary), readout panel, references, abbreviation legend,
                     footer
assets/style.css     design (the "paper" masthead/references, the diagram grid, multi-line
                     node sub-text support)
assets/content.js    ← single source of truth for every node's text and reference list. Edit
                     this file to change what the page says.
assets/app.js        rendering + interaction (builds the diagram and its connector lines from
                     content.js, including the DETOUR routing TREATMENT's route boxes need to
                     clear PREVENTION's own fan-out row; handles the click-to-expand panel on
                     desktop and the bottom sheet on mobile)
```

### Running it locally

No install needed:

```bash
python3 -m http.server 8000
# open http://localhost:8000
```

### Editing content

Open `assets/content.js`. Each entry in `NODES` is one box from the diagram (`meaning`,
`rationale`, optional `dose`/`cautions`, and `refs` pointing at numbered entries in
`REFERENCES`). Add or edit a reference in `REFERENCES` and point to it by `id` from any node.
Never change a node's `label` or `sub` text without the author team's sign-off — those
fields are the algorithm itself, transcribed verbatim from the authors' own figure.
